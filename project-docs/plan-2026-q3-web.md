# План 2026-Q3 — Web Interface v1

> **Статус: ГОТОВО (2026-07-04).** Nitro-сервер (`src/server/`) + Vue SPA (`src/web/`)
> реализованы и проверены вживую (SavePicker → Overview → Resources → Colonists/Bots →
> Colony → 3D-карта). Запуск: `npm run dev` (nitro :3000 + vite :5173). Отчёт — внизу.
>
> Отличия от исходного плана: сервер держит `SaveDocument` в памяти (сессия), клиент шлёт
> команды и получает компактные проекции (не 5MB JSON). Drag построек — нет (ломает игру);
> drag колонистов/ботов/камеры — есть. Ресурсы в 3D — через `InstancedMesh` (GPU-инстансинг,
> один draw call) с per-instance цветом по типу; отдельный GLSL-шейдер не потребовался.

Цель: web-редактор поверх ядра из [plan-2026-q3-engine.md](./plan-2026-q3-engine.md).
Web = **Vue SPA**; `server.ts` (nitro) — только мост между браузером и fs+engine.
Схема сейва — [save-schema.md](./save-schema.md). **Начинаем ПОСЛЕ готового engine.**

Решения (согласовано):
- Vue SPA + nitro-сервер (`server.ts`) для доступа к fs и вызова `core`.
- `settings.json` в проекте: пользователь задаёт папку сохранений игры; по умолчанию `./saves`.
- Сохранение: выбор в UI (новый файл ИЛИ перезапись + `.bak`) — через `SaveRepository`.
- Две связанные проекции: **3D-карта (three.js)** для мира и **2D-карточки** для массовых операций.
- Дать БОЛЬШЕ, чем CLI: не только создавать, но редактировать существующее.

## Зависимости (позже, отдать пользователю)
```
npm i nitropack vue
npm i -D vite @vitejs/plugin-vue
npm i three @types/three          # 3D-карта
```

## Архитектура
```
server.ts                # nitro entry: поднимает web/dist + API
web/
  vite.config.ts, index.html
  src/
    main.ts, App.vue
    api/                 # клиент к nitro (fetch)
    stores/              # состояние: текущий сейв, модель, dirty-флаг
    views/
      SavePicker.vue     # выбор папки/файла (settings.json)
      MapView.vue        # 3D three.js карта
      CardsView.vue      # 2D карточки + массовые действия
      panels/            # инспектор объекта (правка/перемещение)
    three/
      Scene.ts, instancing/  # инстансинг + шейдер для тысяч ресурсов
```
API nitro (тонкие обёртки над `core`):
`GET /api/settings`, `POST /api/settings` (папка игры);
`GET /api/saves` (список .sav), `GET /api/save?path=`, `POST /api/save` (стратегия);
мутации идут через модель на клиенте, сериализация `toXml()` — на сервере при сохранении.

## Функциональность (даём больше, чем CLI)
1. **Settings**: выбрать папку игры (persist в `settings.json`), список сейвов, превью
   (использовать узел `screenshot`, если есть).
2. **3D-карта (MapView, three.js)**:
   - Рендер модулей/коннекций (из `constructions`) простыми примитивами с базовыми текстурами.
   - Персонажи/боты (из `characters`) — кликабельны: инспектор (инфо/правка) + перемещение
     (drag по плоскости → запись `position`).
   - Размещение новых объектов в точке карты (спавн по координатам клика).
   - **Оптимизация ресурсов:** тысячи ресурсов рисуем через InstancedMesh + кастомный
     шейдер (спавн 5к+ в 3D тяжёл) — цвет/тип через инстанс-атрибут.
3. **2D-карточки (CardsView)** — для массовых операций, где 3D неудобен:
   - Ресурсы: добавить +N (в т.ч. +500), удалить по типу, разложить по складам (до лимита слотов),
     выбор контейнера (земля / корабль / конкретный Storage-модуль).
   - Колонисты/боты: список, создать, переименовать, изменить (специализация, показатели), удалить.
   - Колония: переименовать, landing-permissions (проценты, разрешения).
4. **Сохранение**: диалог стратегии (новый файл / перезапись + `.bak`).

## Этапы
1. **W0** — `server.ts` + nitro, `settings.json` (схема, load/save, дефолт `./saves`),
   API `settings`/`saves`/`save` поверх `SaveRepository`.
2. **W1** — Vite+Vue каркас SPA, SavePicker, стор с моделью сейва, round-trip через сервер.
3. **W2** — CardsView: ресурсы (bulk, склады), колонисты/боты CRUD, колония. (Быстрая ценность.)
4. **W3** — MapView 3D: модули+персонажи, клик/инспектор, перемещение.
5. **W4** — оптимизированный рендер ресурсов (instancing + шейдер), спавн по клику.
6. **W5** — превью сейва (`screenshot`), полировка, отчёт (DoD).

## Опирается на API ядра
Требует от engine метод `map(): MapSnapshot` (объекты с `position/orientation/type`) и
сервисы edit/rename/remove/bulk/storage — заложены в engine-плане (Э3).
